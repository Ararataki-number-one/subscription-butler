# 桌面备份、恢复与后台运行

订阅管家的桌面数据位于 `%APPDATA%\订阅管家`。便携程序更新后会继续使用该目录；移动 EXE 不会移动账本。

桌面版启动后直接进入本机工作区，无需设置或输入访问密钥。主进程依据当前 Windows 用户的本机安全配置授予本地管理员会话，内部签名密钥与随机登录哈希留在数据目录，不交给网页。已有安全配置及 MFA 密文不会被重置。网页自托管、成员凭证和 API 仍保留各自的验证与权限规则；切换成员身份时按成员权限访问。可从原生菜单“应用 → 重新进入本机工作区”回到本机管理身份。

## 打开软件

桌面版按当前 Windows 用户的本机数据目录自动初始化安全配置并进入工作区，不要求输入密钥；已有配置会保留，以继续解密 MFA 和历史安全设置。网页登录和协作凭证仍在服务端验证。主进程只为当前本机窗口设置 HttpOnly 会话，网页没有公开自动授权接口。

优先使用安装版，从固定目录启动；便携包每次需要解压到临时目录，冷启动可能较慢。“应用 → 重新进入本机工作区”可恢复本机窗口的会话。

## 创建与恢复本机备份

在“维护 → 创建本机加密备份”选择保存位置。`.sbbackup` 包含 SQLite 账本、登录配置、已加密保存的登录凭据、MFA 与邮件设置，以及桌面通知偏好。运行中的数据库通过 SQLite 在线备份 API 获取一致快照，包含已提交的 WAL 内容。

备份整体使用 AES-256-GCM 加密，随机密钥由 Windows 安全存储（DPAPI）保护。只能由原电脑上的原 Windows 用户恢复。重装 Windows、换电脑或删除用户配置后，DPAPI 密钥可能无法再解开；此功能是本机恢复点，不用于跨电脑迁移。备份仍是私有账本，应存放在自己的磁盘，不要放入公开仓库。

“维护 → 恢复备份”会先解密并验证文件清单、逐文件 SHA256、SQLite 完整性、外键、迁移历史、账户数量、各币种金额摘要，以及 MFA 密文与原登录配置是否匹配。清单只接受固定文件名；不接受相对跳转路径、绝对路径或重复条目。验证失败时保持当前服务和账本。较旧的兼容 schema 会先在暂存目录升级，再验证账户与金额保持一致；应用不能读取比其支持版本更高或不识别的 schema。

确认恢复后，程序停止本地服务，自动保存一份恢复前的加密备份，并用恢复日志保护文件替换。恢复后自动进入本机工作区；网页访问密钥及 MFA 配置继续保留。服务启动失败时自动恢复原文件；意外关机后，下次启动会按恢复日志回滚未完成的替换。自动恢复点位于数据目录的 `backups`，保留最近 5 份，可从“维护 → 从自动恢复点回滚”选择。每次软件版本变化，在数据库迁移前也会生成恢复点。

如果维护失败后无法重新打开，请保留整个数据目录，尤其是 `restore-journal.json` 与 `.restore-*` 暂存目录。不要自行删除这些文件，也不要用旧版软件强行打开已升级的数据库。程序还检查 `installed-version.json`：即使 SQLite 迁移没有变化，较旧版本也不能打开较新版本使用过的数据目录，避免覆盖新字段。用当前或更新版本的软件选择升级前的兼容恢复点回滚数据；数据回滚不会降级正在运行的软件。

浏览器中尚未到达本地服务的未提交操作不在 SQLite 备份中。网页入口应先提交这些操作再恢复；原生菜单会检测当前地址的 IndexedDB 队列。明确确认恢复后，队列先单独加密保存为 `backups/offline-*.sbqueue`，旧缓存和会话随后清除。重新登录管理员后，可用“维护 → 恢复已保存的未提交队列”人工重新排队，再在工作台检查并提交。队列不会自动写入账本；原命令编号保留，服务端会重新验证权限、版本和重复编号。这些独立导出不会被自动恢复点的 5 份保留策略删除。

本地地址的端口首次分配后记录在 `server-port.json`，后续启动复用相同空闲端口，让网页缓存和离线队列保持同一 origin。端口被其他进程占用时，程序停止启动并提示解决占用，不会悄悄换端口。不要删除此配置来绕过占用；换地址会使原地址下的未提交队列无法自动读取。

## 托盘与到期通知

“应用 → 关闭窗口到托盘”默认启用。关闭主窗口后，本地服务、每 5 分钟汇率更新和通知检查继续运行。点击托盘图标返回窗口；从菜单“退出”或托盘“退出订阅管家”彻底停止服务。可关闭该选项，让关窗直接退出。

“到期通知”使用本地数据库内的订阅和出租收款日期及提前提醒天数，日期按上海时区计算。程序运行期间启动后检查一次，此后每 5 分钟检查。通知文本只显示到期数量，不在锁屏显示邮箱、联系人或金额；点击通知返回软件查看。同一日期、同一事项和到期日期的通知每天去重，重启不会重复发送；续费修改日期后的新事项可以再次提醒。Windows 不支持通知或投递失败时不会写入已提醒记录。此功能不创建计划任务，程序完全退出后不发送系统通知。

## 网页可选桌面桥接

桌面版的 `window.teamAccountManagerDesktop` 提供：

- `maintenance.createBackup()`：打开本机保存对话框；返回 `{cancelled, fileName?, createdAt?}`。
- `maintenance.restoreBackup()`：选择备份并经过原生确认；返回 `{cancelled, restoredAt?}`。
- `maintenance.listRestorePoints()`：返回 `{name, modifiedAt}[]`，不提供绝对路径或备份内容。
- `maintenance.restorePoint(name)`：只能选择列表内的恢复点，并经过原生确认。
- `getPreferences()` / `setPreferences({closeToTray?, notifications?})`：读取或修改桌面偏好。

桥接只接受主窗口、主 frame、当前端口的 `127.0.0.1` 页面。网页备份、恢复和恢复点接口还向本地服务核验管理员身份，当前成员凭证优先，不能用附带的管理员 Cookie 提升权限。原生维护菜单是当前 Windows 用户的本机恢复入口，不依赖遗失的登录密钥；队列人工重排队仍要求管理员登录。网页不能指定任意读写路径；备份私钥、配置、MFA 秘密和数据库内容不会通过这些接口返回。网页版以及旧客户端应先检查接口是否存在，再显示相关入口。

## 验证范围

`npm run desktop:test` 使用合成 SQLite 数据验证在线备份、加密封装、完整恢复、MFA 配置保持、损坏清单、异常路径、金额不一致、暂存篡改、启动失败回滚、恢复日志、升级保护、恢复点保留及通知去重；不会读写安装中的真实账本。

打包后可用 `--maintenance-smoke-test` 加 `SUBSCRIPTION_BUTLER_USER_DATA=<独立测试目录>` 运行无窗口验证。该路径只在明确的测试参数下生效，不能指向默认数据目录。检查捆绑 Node、数据库初始化、健康检查、登录页、真实 Windows 安全存储加密、备份恢复与恢复后重启，并写入测试目录的 `smoke-result.json`。通知的实际显示还取决于 Windows 通知设置；自动测试验证提醒数据和去重逻辑，未替代人工检查托盘交互。

`--ui-smoke-test`（也可用 `--first-run-smoke-test`）要求全新的独立测试目录。它使用始终隐藏的自有窗口，按真实桌面启动路径自动初始化私有配置并进入本机工作区，确认没有密钥输入或设置页、会话为管理员且 Cookie 对页面脚本不可读；继续通过工作台表单新增客户、订阅、分配、续租和部分收款，查看历史，并停止重启后台及重建窗口验证仍自动进入和保留账本。不使用额外的测试授权接口，不控制用户屏幕。结果写入 `ui-smoke-result.json`；此模式须在最新页面和运行环境准备完成后对实际发行包执行，源码静态检查不代表它已通过。
