# 运营模型与账务规则

本文件说明已经实现的运营数据与账务接口。V1 的 SQLite 表继续保留，V2 运营记录存入迁移 `0022_operations.sql` 新增的表；运营操作不会删除旧表或用一个虚构主账号补齐 Pro 收益。

## 统一记录与稳定身份

核心关系是：客户 → 订阅 → 位置 → 租赁 → 账单 → 收支记录。订阅记录服务、套餐、标签、分组和原币成本；模板提供可复用的周期、容量、手续费与分摊规则。位置是真实可分配的账号或名额，租赁保存客户、自用状态、服务日期、收费和操作历史。

每条运营记录都有 `id`、`kind`、`data`、`revision`、`updatedAt`。新记录的 ID 由命令 UUID 派生，因此同一命令在设备和服务器上执行不会产生另一个业务 ID。旧记录使用 `legacy:subscription:旧spaceID`、`legacy:slot:mother:旧母号ID` 等映射，`data.legacy.sources` 保留来源表与行号。

Business 同邮箱或被标记为母号的子记录归到一个母号位置。母号有出租资料时以母号资料为准；母号未登记而重复子记录有出租资料时保留该资料。Pro 只迁移实际拼车成员，不生成母号租赁。旧收款只迁移为带来源的现金收款，不猜客户、账期或账单，也不把当前订阅报价伪装成一笔历史购买付款。

## 旧界面改动与设备来源

读取运营快照会检查本机旧表的指纹。只有仍由旧来源管理的字段会刷新；在运营界面修改过的字段会退出旧来源管理，后续旧表刷新不会覆盖它。明确开账单或续租后，租赁身份与实际在用状态归运营层管理。旧来源删除后仍保留记录与来源，非账务库存适用时标记停用或退出；已经确认的收款保留有效状态、金额与汇率，仅提示来源缺失，需要运营中心明确退款或作废，读取快照不会代替用户取消一笔历史交易。

`ops_legacy_owner` 单独记录本机迁移桥的来源权限，权限不随账本复制。接收远端记录时移除本机来源管理权，保留来源说明。空旧表的新设备不会把远端旧账本记录误判为已删除；本地旧表与已同步的稳定 ID 相撞时不会自动拼接，而会记录 `legacy.conflict` 审计，等待明确核对。两个独立旧账本不能仅因行号相同就当作同一客户或订阅。

## 租期与位置

日期按亚洲上海时区的业务日期处理。服务期使用半开区间 `[开始日, 结束日)`；相邻的两个周期共享边界日期，不重复计一天。月、季度和年保留 `cycleAnchorDay`，短月暂时落到月底，随后恢复原锚点，例如 1 月 31 日 → 2 月 28 日 → 3 月 31 日。闰年的 2 月 29 日年度锚点也会在下一闰年恢复；旧租赁优先保留原付款日，不以加入日覆盖付款锚点。

加入出租租赁时创建第一张明确账期的账单，自用租赁占用位置但没有应收。续租从上期结束日开始，追加下一期账单和历史事件，递增 `periodVersion`。换号记录原位置、目标位置和生效日；此前的位置占用与成本归属仍保留。退出停止租赁并保留历史，不自动抹掉应收或收款。已有有效租赁的位置或订阅必须先退出租赁，才能停用。

提前续租只预约下一账期，不推进物理换号或退出的生效日。续租历史保存操作日期及独立的 `periodStart`、`periodEnd`；加入、换号、退出的日期顺序单独检查，已经提前续过下一期的客户仍可在当前期换号或退出。未来账单继续保留，需取消应收时使用明确优惠或作废操作。

正常更新要求 `expectedRevision`。续租还要求当前 `expectedPeriod`，所以重复点击、离线排队中的过期命令或另一设备已经续过的操作不会再延长一次。批量续期和批量状态变更使用整批事务：一条冲突时整批不写入，刷新后再选择要操作的记录。

## 应收、收款与调整

账单保存原币应收、账期、到期日和创建时的冻结汇率。账单余额以账单原币计量，实际收款和补款分别形成独立收支记录；手续费不改变客户已清偿的本金。异币收款保存收款时的账单币种汇率和抵扣金额，不经一次已经取整的美元金额再换算回原币。

退款必须引用原有效收款并说明原因，累计原币退款不能超过原收款。退款按原收款的应用比例恢复账单余额；退款本身是一笔新现金交易，冻结登记时的汇率。退钱不会自动免除原账单：取消服务或减少应收时，还需明确优惠或作废。

优惠和作废必须有原因。优惠不能把应收降到已收金额以下；有已收余额的账单必须先退款才能作废。已有退款的原收款不能直接作废。作废保留原金额、汇率与来源，只改变有效状态并写审计；不能通过复制记录复活作废账务。

购买与续订费用保存原币金额、手续费百分比、手续费金额、合计、付款日和服务期。费用记录保留支付渠道，以及购买时的分摊规则和位置权重。实际收支、账单汇率和这些费用快照不随以后汇率、手续费设置或分摊权重变化重写。

## 三种报表口径

| 口径 | 收入 | 成本 |
| --- | --- | --- |
| 现金 | 付款日内的有效实收减实际退款 | 付款日内的有效购买与续订支出 |
| 按期 | 明确账期的净应收按服务日分摊 | 带服务期的实际费用按服务日分摊；无服务期费用计入付款日 |
| 当前预计 | 当前有效租赁的约定收费月度参考值 | 当前订阅含手续费的月度参考成本 |

三种口径分别给出收入、成本和净额，不能相加当作一个“总收益”。旧实际收款缺少账期时只计现金，并在报告中提示未归属。报告日期同样使用半开区间；未收明细在报告结束日截点计算，后来才发生的收款不会提前清偿此前报表的余额。

金额存为币种最小单位的安全整数。USD 和 CNY 分别冻结；原币到人民币直接按有理数换算，避免中转美元分币取整导致人民币少几分钱。报表行中费用是正数，展示净额时费用行取负号；每行有 `sourceId`、`sourceKind` 和订阅、客户关联，可打开原始账单、收款、费用或租赁。

按客户查看时，成本只按该客户在用位置及实际历史区间分摊，不把整笔订阅成本重复扣给每个客户。现金费用的客户分组是归属分摊；整体现金报告仍只统计一次实际支出。没有服务期、无法可靠关联客户的旧购买成本不会猜分给某个客户。

## 年费与固定权重

年费先按实际服务天数摊销，每天取累计整数分摊的差值。相邻月份合计与原始费用一致，包括闰年和不足整月的期间。`fixed` 表示按位置的固定权重分配，空置位置的成本仍归订阅；`daily` 表示按当天实际在用位置的权重分配，当天无人使用的成本也仍归订阅。

`fixed-amount` 使用位置的 `fixedCostMinor`：以订阅原币记录每个订阅周期的固定分摊额，合计不能超过含手续费周期成本。实际购买时将固定金额按登记服务期折算成周期合计，冻结美元和人民币份额；合计也不能超过这笔实际购买成本。每日分摊同时对齐费用总额与各固定份额的整数边际，总费用、各位置份额与残余均可对账，不产生负的未分摊成本。固定份额对应空置时段及费用残余仍归订阅。

换号前后分别使用相应位置。购买费用捕获当时规则和权重，后来修改规则只影响当前预计和后续购买费用。位置权重必须是正整数，自用位置参与成本分摊。

## 当前汇率与保本定价

当前预计读取既有 `fx_rate` 缓存。程序原有的每 5 分钟更新会自然反映在预计报表；缺少汇率时返回待计算及币种清单，不写 0 代替未知金额。实际收支和应收仍使用自己的冻结汇率。

`calculatePricing` 在原币、单个订阅周期内计算含手续费总成本、按实际出租位置数的保本价及目标毛利率价格。目标毛利率是利润占售价的比例，价格向上取整；自用和空置减少可用于回收成本的出租数量。

## API 与导入

```ts
const store = new OperationsStore(sqlite);
store.snapshot(actor);
store.execute({ id: commandUUID, type: "rental.renew", payload: {
  id: rentalId, expectedRevision, expectedPeriod
}}, actor);
store.report({ from, to, subscriptionId, customerId, channelId }, actor);
store.changes(afterSeq, limit, actor);
store.audit(limit, actor);
```

`snapshot` 包含客户、模板、订阅、位置、租赁、账单、收支数组；各项是完整 `OpsRecord`。`plans` 是 `templates` 的兼容别名，不是另存的一组记录。成功操作返回 `{ok:true,replayed,changedIds,snapshot}`；验证、冲突、幂等 ID 复用和历史不可改写错误有独立 `OperationsError.code`。

命令包括 `customer.save/archive`、`template.save`、`subscription.save/renew/disable`、`slot.save/disable`、`rental.join/renew/exit/switch`、`renewal.batch`、`status.batch`、`bill.issue/discount/void`、`entry.receive/refund/cost/void`、`import.commit`。

CSV 解析与预览由界面负责，提交格式为 `import.commit {rows:[{type,payload}],sourceName}`。引擎再次验证每行，在一个事务内提交；错误整批回滚。批次命令 ID 和行规范化指纹防重复，客户重复只在导入时按名称、联系方式、邮箱组合检测，普通新增客户不会强制把同名人员合并。

同步入口 `applyReplica({id,records:[{id,kind,data,expectedRevision,sourceRevision}],reason},actor)` 只允许管理员。每条记录做完整格式、关系、账务余额及冻结金额验证；不能信任客户端 `legacy` 标记跳过验证。来源版本可按明确同步决议对齐，本地预期版本仍必须匹配，变更序号和审计继续保留。
